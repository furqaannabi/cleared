# Demo accounts read one real YouTube channel the team owns

**Date:** 2026-10-10
**Status:** Accepted
**Decided by:** Furqaan (William to agree)
**Supersedes:** none

## Context
A demo account's YouTube channel is made up, so nothing can be read from YouTube for it, and the go-ahead and the live check both read YouTube. Judges cannot connect their own channels: Google caps an unverified app at 100 users. PRODUCT.md already says the hosted demo needs pre-connected demo accounts and sample files, and the rules say a demo account runs the same code as any other.

## Options
1. **A shared channel the team owns.** One real channel, connected once. Every demo account reads from it, read-only. The sample clip is uploaded there and public. The live check is real.
2. **A stand-in YouTube for demo accounts.** Any video could be clicked through, but it is different code from a real account, and the live check a judge sees is not real.
3. **Demo deals stop at approved.** Nothing to set up, but a judge never sees the go-ahead, the live check or the payout.

## Decision
Option 1.

## Consequences
- The team makes the channel, connects it once through the normal connect flow, and marks it as the demo channel.
- Every read of YouTube for a demo account uses that channel's read-only access. Nothing else about a demo account's code differs.
- The channel holds the sample clip, public, with a description that meets the sample deal's written items.
- A demo deal can only be finished with the sample clip. The go-ahead step offers its link.
- The channel's access must not expire, so the Google app has to leave Testing before the channel is connected.
- Many demo deals pointing at one video is expected: each has its own hold and its own live check.
- This also answers how a demo account gets past the draft check's sample to a finished deal. How a judge approves a PayPal hold is still theirs to do with a sandbox buyer account.

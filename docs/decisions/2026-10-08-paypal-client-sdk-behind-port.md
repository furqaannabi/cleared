# The backend calls PayPal through its server SDK, behind our own interface

**Date:** 2026-10-08
**Status:** Accepted
**Decided by:** Furqaan
**Supersedes:** none

## Context
The money path makes about ten kinds of PayPal call across Orders, Payments, Payouts and Webhooks. Each must carry a request id, be safe to send twice, and be replaceable in tests by something that can decline, time out or answer twice on demand. No backend code calls PayPal yet.

## Options
1. **PayPal's server SDK behind our own interface.** The official `@paypal/paypal-server-sdk` makes the Orders and Payments calls, wrapped in one small "PayPal port" the money code depends on. Payouts and webhook verification, which that SDK does not cover (checked against version 2.5.0), use plain HTTP inside the same port. The SDK is generated by APIMatic, a hackathon sponsor. Needs a check that it runs on Bun.
2. **Plain HTTP only, behind our own interface.** No dependency and no Bun risk; every call and its token handling are ours to write and keep correct.
3. **The SDK called directly.** Fastest to start; tests would have to mock the SDK, and the request-id and retry rules would be scattered.

## Decision
Option 1. The money module depends only on the port. The real port uses PayPal's server SDK where it covers the call and plain HTTP where it does not.

## Consequences
- New dependency: `@paypal/paypal-server-sdk`. It replaces hand-written request, response and token code for Orders and Payments. It is server-side only, so it adds nothing to the frontend bundle.
- The port fixes PayPal's address to the sandbox in code (MP-BR-10) and is the only place PayPal's secret is read.
- Tests use a fake port; a small suite runs the real port against the sandbox by hand ([test tooling decision](2026-10-08-backend-test-tooling.md)).
- If the SDK does not run on Bun, the port is rewritten on plain HTTP (option 2) with no change to the money module, and a new record supersedes this one.
- APIMatic's Context Plugin stays the coding aid named in PRODUCT.md; this adds a second use of APIMatic's tooling.
